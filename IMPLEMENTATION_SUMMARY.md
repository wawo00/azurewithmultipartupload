## Technical Implementation Details

### Architecture Pattern
```
Producer (WMARecorder)
    ↓
File Size Monitor (Timer) → FileChunkManager (256KB chunks)
    ↓
BlockingQueue<ChunkData>
    ↓
Consumer (UploadQueue with 2 workers) → HTTP Upload
```

### Thread Safety Mechanisms
1. **Synchronized blocks** in FileChunkManager for critical sections
2. **BlockingQueue** for thread-safe producer-consumer communication
3. **ExecutorService** for managed thread pool
4. **Volatile flags** for state visibility across threads
5. **Object locks** for resource coordination

### File Path Format
- Pattern: `/data/user/0/com.wally.sdkdemo/cache/audio_20251120_070936.aac`
- Format: `audio_YYYYMMDD_HHmmss.aac`
- Generated by: `SimpleDateFormat` in AudioStreamController

### Upload Format
- Protocol: HTTP POST with `multipart/form-data`
- Boundary: `----WebKitFormBoundary{timestamp}`
- Fields: file data, chunkIndex, offset, fileName, isLastChunk, chunkSize, timestamp

### Error Handling
- **Retry mechanism**: Up to 3 attempts per chunk
- **Exponential backoff**: 1s, 2s, 3s delays
- **Failure callbacks**: Propagated to ControllerListener
- **Graceful degradation**: Continue processing other chunks on failure

## Production Readiness Notes

### For Android Deployment
1. **Replace WMARecorder**: The current implementation uses `javax.sound.sampled` which is not available on Android. Replace with `MediaRecorder` or `AudioRecord`.
   
2. **Network Security**: 
   - Use HTTPS in production
   - Remove `android:usesCleartextTraffic="true"` 
   - Implement proper certificate pinning

3. **Authentication**: Add authentication headers to upload requests

4. **Background Service**: Consider using a foreground service for long recordings

5. **Battery Optimization**: Handle Doze mode and app standby

### Configuration Recommendations
- **Chunk Size**: 256KB is optimal for mobile networks
- **Worker Threads**: 2 workers balance performance and resource usage
- **Retry Attempts**: 3 attempts with exponential backoff
- **File Check Interval**: 1 second provides good responsiveness
